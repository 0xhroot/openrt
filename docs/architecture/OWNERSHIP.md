# OpenRT — Architecture Ownership Map

**Status:** Accepted
**Date:** 2026-09-17
**Companion to:** `docs/roadmap/ROADMAP.md`, `docs/architecture/adr/`

This map records **which phase owns each subsystem**, the **Rust crate** that
will implement it (naming per ADR-007), and the **storage namespace** it owns
(base rule ADR-006: everything lives in the Phase 1 foundation store manager —
overlays may index, never copy).

Rules of use:

1. A new subsystem must be allocated a crate and storage namespace here
   **before** implementation (ADR-007).
2. One owner per subsystem; cross-phase features are listed as "extends" or
   "on <owner phase>" — never duplicate ownership.
3. Storage namespaces are versioned; consumers address by `namespace + key`.

> resolved as documented in `docs/architecture/phase1/PHASE1_IMPLEMENTATION.md`:

> allocated; `openrt-xtask` is deferred (no build tooling needed in P1). Term

## Phase 7 — TOOL FABRIC

> **Reconciliation (2026-09-24):** ROADMAP v0.3 adds Phase 7 (originally a
> 6-phase doc; `project-complete-plan.txt` called this “Phase 7 — Tools /
> Tool Fabric”). Phase 2 continues to own the existing `screen.*`/`input.*`/
> `browser.*`/filesystem/terminal/python **tools** and the computer-use loop.
> Phase 7 owns the **platform abstraction layer** those tools (and later
> browser/MCP tools) sit on: environment discovery, capability negotiation,
> compositor/WM adapters, and the high-level ComputerControl API. No second
> tool registry, gate, or permission system.
>
> **Phase 7B (ROADMAP v0.4):** after 7A (platform layer, frozen), 7B adds
> the remaining tool fabric — Tool Fabric core metadata/discovery/errors,
> browser automation, MCP integration, database tools, application tools,
> Excel/PPT/DOCX, cross-tool orchestration. New crates are allocated below
> **before** implementation (ADR-007); every 7B tool registers on the
> existing `openrt-tools` ToolRegistry through the existing GateExecutor.
> Phase 2 still owns the Phase 2 `browser.list`/`browser.activate` window
> tools — 7B's structured `browser.*` tools are additive and never replace
> them.

## Phase 8 — SANDBOX + ISOLATED EXECUTION FABRIC

> **Reconciliation (2026-09-25, ROADMAP v0.5):** Phase 8 does not create a
> second sandbox, policy engine, resource manager, registry, or audit system.
> `openrt-sandbox` (Phase 2.4) is extended into the **single sandbox
> authority**: unified `SandboxRequest`/`SandboxPolicy`/`SandboxHandle`/
> `SandboxResult` with identity + policy digest + explicit lifecycle states,
> sitting between the existing GateExecutor policy/Sovereign checks and
> execution. `openrt-resources` `ResourceGate`, `openrt-netpol`/`openrt-modes`
> (egress intent + mode gate), `openrt-computer` PathJail/terminal process
> control, and `openrt-audit` (chained, ADR-002) remain the authorities in
> their own areas — Phase 8 consumes them and adds execution-level
> enforcement. New storage namespace allocated under ADR-006 before
> implementation (crate-allocation checklist above).

| Subsystem | Crate | Storage namespace | Notes |
|---|---|---|---|
